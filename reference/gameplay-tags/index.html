    Gameplay tags¶

    Designer · reference · No code

    Generated from source — do not edit by hand.

    This page is written by Docs/Manual/tools/gen_reference.py from the plugin's headers. Edit the source comment and re-run the generator instead. See Docs/Manual/tools/README.md.

    Every gameplay tag XenoCore declares. There are two kinds:

    • Native tags are declared in C++ (XenoCoreGameplayTags.h / .cpp) because code names them. C++ uses the symbol in the C++ symbol column, for example XenoCoreGameplayTags::Status_XenoCore_InBattle.
    • Ini tags are declared in the plugin's Config/Tags/XenoCoreTags.ini because only data (abilities, input data, state trees) picks them.

    Both kinds appear in the editor's tag picker. Matching is hierarchical: a check for Status.XenoCore.Reaction also matches Status.XenoCore.Reaction.Break.

    Fails silently: a tag declared twice, or renamed

    Declare a new tag in one place only. If C++ looks a tag up by its string name and the tag is later renamed, the lookup returns an empty tag. Nothing is logged; the feature that depends on the tag simply stops. Add your own tags to your own tag .ini or native file, and never edit XenoCore's in place.
